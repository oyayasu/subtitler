# Subtitler 0.8.3 Mac export and chapters update

Status: locally tested; the Mac build is pending verification. This update builds only for Apple Silicon macOS. No Windows build is requested or produced.

## Cause

The export dialog generated buttons with `data-export` attributes, but the shared click handler no longer handled those attributes. The files could be generated by the export module in tests, while the user-facing buttons did nothing. The original shipped bundle reproduced this failure in the DOM regression harness.

## Every change to test

1. **All export buttons respond.** DOCX, TXT, SRT, CSV, XLSX, timing JSON and editable .subtitler project export all reach their existing export paths. Clicking a format's extension or description works as well as clicking the button itself.
2. **Export preparation is visible.** The dialog displays “Preparing export…” while the file is being prepared or saved.
3. **Repeated clicks are ignored while exporting.** The format buttons and timestamp option remain disabled until the operation completes, fails or is cancelled. Only one export starts at a time.
4. **Cancellation allows retry.** Cancelling the native save picker keeps the export dialog open and re-enables its controls.
5. **Failures are visible in the dialog.** A generation or write error appears beside the export controls, which become usable again. The app does not silently dismiss the failed export.
6. **Exports use a stable snapshot of current applied edits.** The current open document takes precedence over an older entry in the in-memory project list. Edits arriving later cannot mutate an already started export.
7. **Help copy describes project export correctly.** Editable native .subtitler exports remain independent copies and use the existing audio-preserving document writer. Other document formats retain their existing export behavior.
8. **Windows compatibility is retained.** The verified 0.8.2 save-folder move/path-alias fixes were brought forward into the standalone repository's 0.8.1 base. Application and file-format identifiers remain unchanged; this patch does not redesign the document format.
9. **New regression coverage clicks the shipped bundle's UI.** Added DOM coverage and a full Chromium test for all seven formats, nested button labels, cancellation, errors, repeated clicks, current edits and linked-project routing. The prebuilt Safari-compatible bundle and its integrity manifest have been regenerated.

## Local validation

- 59 JavaScript model/export/chapter regression tests passed.
- 12 Python alignment/build-lock tests passed.
- 30 compiled Rust storage, embedded-audio, process, recording-ownership and shared-export tests passed on Linux.
- DOM execution of the actual shipped bundle passed all seven formats for both standalone and Storyboard-linked documents, including Unicode, timestamps, cancellation, retry and duplicate-click protection.
- Independent python-docx, openpyxl, CSV and JSON readers accepted the files produced by those UI actions.
- Original pre-fix bundle reproduced the inert-button failure under the same DOM harness.
- Frontend bundle integrity, source imports, version/identity checks and Mac builder shell syntax passed.

The local environment cannot launch Chromium because its process socket is denied. Browser tests and an Apple Silicon Mac build run in a separate workflow. Native save-picker interaction and installed WebKit behavior still need practical testing on the user's Mac. No speech model run is needed to test the export actions or manual chapter editing.

## Practical testing after installation

1. Open an existing transcript containing subtitles. Export each of the seven formats; click both the extension and the description inside the buttons.
2. Open DOCX and XLSX in a compatible reader. Check accented text, Japanese text, subtitle order, word rows and timing values. Export TXT and DOCX with timestamps both on and off.
3. Open the SRT in a subtitle editor and verify the first and last subtitle's text and timing.
4. Cancel a save picker, choose a format again, and confirm it still works.
5. Use an unwritable or unavailable destination where possible. Confirm the dialog reports the error and permits another attempt.
6. Double-click a format during preparation. Confirm that only one save operation starts.
7. Apply a subtitle edit, then export immediately. Confirm the latest text is present.
8. Export a .subtitler copy, open it independently, and verify its transcript and available embedded audio. The original document's identity and Storyboard connection must remain intact.
9. Repeat an export from a Storyboard-linked transcript. Confirm the existing shared export routing and recording ownership remain intact.

## Chapters and reference text

1. **Chapters is optional.** Open Chapters beside Reference text. Use ＋, enter a chapter name and start time, choose Chapter or Subchapter, then Save chapters. Times accept seconds, MM:SS or HH:MM:SS.mmm. Editing or removing a marker does not cut or edit the recording.
2. **Import proper Word headings.** Import Reference text from a DOCX using real Heading styles. Heading 1 becomes a chapter; Heading 2 becomes a subchapter. Heading levels through 6 and inherited heading styles are retained. Document titles and heading names are excluded from spoken reference words. Bold or large normal text is not treated as a heading.
3. **Match before trusting an imported time.** When reference text reliably matches an existing timed transcript, its chapter starts are placed at matched words. Otherwise they remain visibly unplaced. Match timings can place them after recognition/alignment, or use Match imported headings against the current transcript. You can enter times manually at any point.
4. **Jump using waveform flags.** Placed chapters have small flags with immediate chapter labels on hover or keyboard focus. Clicking a flag jumps to its time. The Chapters button shows the marker count.
5. **Export real headings.** DOCX uses Title for the document name and proper Heading styles for chapters. TXT includes chapter names. A chapter boundary within a subtitle can split the document paragraph without cutting or losing words. SRT, CSV and XLSX keep their subtitle layouts and timings.
6. **Unplaced markers are preserved.** DOCX/TXT omit unplaced or unreviewed markers and show a warning before export. Editable .subtitler projects and timing JSON retain chapter metadata, including unplaced entries. Chapter IDs survive saving, reopening and Undo/Redo.
7. **Manual times remain manual.** Imported markers can follow their matched word when word timing improves. Entering your own time makes that marker manual. Changing to a different recording invalidates automatic anchors and asks for review of manual times; relinking the same recording preserves them.
8. **Save and remove normally.** Use the × beside a chapter to remove it, then Save chapters. Escape or Close discards changes in the chapter dialog. Saving an unchanged reference view retains imported headings. Reimporting reference text refreshes imported markers while retaining independent manual markers.

After installation test manual add/edit/remove, invalid or out-of-range times, DOCX Heading 1/2 import, unmatched/empty headings, matching and manual overrides, waveform flag jumps, save/reopen, Undo/Redo, and DOCX navigation headings. Adding or removing a chapter must never modify the source audio or the SRT cue timings.
